## ลำดับภาพและการซ้อน

ลำดับท่าเชฟที่แนะนำ: 01 → 02 → 03 → 04 → 05 → 01
เริ่มทดลองที่ประมาณ 8–10 เฟรมต่อวินาที แล้วปรับตามจังหวะเกมจริง
แสดง slash สั้น ๆ ในจังหวะ 03–04 และเปลี่ยนสถานะเค้กตามการหั่น

ลำดับเลเยอร์จากหลังมาหน้า:
พื้นหลังร้านเดิม → เชฟ → โต๊ะบังช่วงขา → เค้กบนโต๊ะ → slash → UI

แต่ละท่าเชฟมีมีดอยู่ในมือแล้ว มีดแยกไฟล์มีไว้เป็นทางเลือกสำหรับเอฟเฟกต์หรือแอนิเมชันของพร็อพ
ไม่จำเป็นต้องวางมีดแยกซ้อนทับมีดในมืออีกเล่ม

ไอคอนอุปกรณ์เป็นภาพสื่อความหมายของการเขย่ามือขวา ไม่ใช่ภาพวงจรหรือรุ่นเซนเซอร์จริง
ตัวจับเวลา คะแนน และข้อความตามสถานะควรใช้ข้อความจากเกมจริง ไม่ฝังตัวเลขไว้ในภาพ

## นำเข้า Unity

เมื่อพร้อมใช้งาน ให้คัดลอก PNG ที่ต้องการเข้าโฟลเดอร์ Assets ของ Unity ด้วยตนเอง
ค่าตั้งต้นที่แนะนำสำหรับภาพเหล่านี้:

- Texture Type: Sprite (2D and UI)
- Sprite Mode: Single
- Alpha Source: Input Texture Alpha
- Alpha Is Transparency: เปิด
- Mesh Type: Full Rect
- Filter Mode: Bilinear
- Wrap Mode: Clamp
- Generate Mip Maps: ปิดสำหรับ UI
- ใช้ Pixels Per Unit เดียวกันสำหรับทุกเฟรมในชุดเชฟ และทุกสถานะในชุดเค้ก

เชฟทั้ง 5 ท่าและภาพเค้กทั้ง 5 ไฟล์ใช้ผืนภาพ 1254 × 1254 พิกเซล
ขนาดไฟล์อื่นและขอบเขต alpha อยู่ใน ASSET_MANIFEST.json

ภาพเหล่านี้สร้างเป็นแต่ละเฟรมแยกกัน ไม่ใช่ตัวละคร rig กระดูก:
ควรจัด Pivot/ตำแหน่งเท้าเชฟและฐานจานให้ตรงกันใน Unity และตรวจการกระโดดของภาพขณะสลับเฟรม
รายละเอียดรูปทรงอาจต่างกันเล็กน้อยระหว่างเฟรม เหมาะเป็นชุด sprite ต้นแบบสำหรับจัดแอนิเมชันต่อ

## ข้อมูลการสร้างและตรวจไฟล์

- PNG ทุกไฟล์ผ่านการตรวจว่าเปิดอ่านได้ มี alpha โปร่งใส 0 และมีส่วนทึบ 255
- ภาพที่ส่งมอบใช้เชฟผมสั้น ชุดขาว กางเกงขาว ผ้าผูกคอแดงตามหน้าเมนูหลัก
- ไม่รวมเชฟผมยาวจากคอนเซปต์เก่า
- ไม่แก้ไขโค้ด ฉาก Unity หรือไฟล์เชฟต้นฉบับ
- ข้อความสั่งสร้างฉบับเต็มของแต่ละไฟล์อยู่ใน GENERATION_PROMPTS.md
